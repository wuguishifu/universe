# youtube-music-mobile ("Tunes")

An Expo (SDK 58) music player for the library on [youtube-music-service](../service). Share a
YouTube video or playlist to it and the server downloads the audio; it then plays from the server,
or from the phone once downloaded. It's for personal use and sideloading, not the App Store.

## What it does

- **Share sheet**: "Add to Tunes" in the iOS share sheet (a share extension from `expo-share-intent`)
  takes a link from the YouTube app, Safari or anywhere else to the add screen, which queues it on
  the server straight away. Playlists are imported as playlists. The + in the library takes a pasted
  link, and `youtubemusic://add?url=<link>` deep links there too.
- **Library**: search, sort, filter (on the phone / not ready yet), play or shuffle. Tracks still
  downloading on the server show their status and appear when ready (the list polls meanwhile).
- **Playlists**: create, rename, reorder, remove, delete; imported YouTube playlists can be synced.
- **Player**: background playback, lock screen and Control Center controls with next/previous,
  shuffle, repeat (all/one), queue (play next, add to queue, remove), and optional volume levelling
  from the server's loudness measurements.
- **Downloads**: per track, per playlist, the whole library, or automatically for everything. Stored
  in the app's Documents folder; removed tracks are cleaned up. Downloaded tracks play offline, and
  the library itself is cached, so the app works without a connection.

## Code map

- `app/`: expo-router screens. Tabs (`library`, `playlists`, `settings`) each have a stack; `player`,
  `add`, `edit/[id]` and `add-to-playlist` are modals.
- `src/lib/player.ts`: the queue, on expo-audio's `AudioPlaylist` (native gapless queue + lock
  screen). The native playlist restarts the current track if anything before it changes, so queue
  edits only ever touch what's after it.
- `src/lib/downloads.ts`: the on-phone cache. The files are the source of truth.
- `src/lib/queries.ts`: react-query, persisted to SQLite (`expo-sqlite/kv-store`).
- `src/lib/settings.tsx`: server address and toggles in SQLite, the token in the keychain.

The workspace root has the web apps' React 19.0, so `metro.config.js` resolves every `react` import
to this app's copy.

## Running it

It needs a dev build (native modules), not Expo Go. `ios/` and `android/` are generated by
`nx prebuild youtube-music-mobile` and not committed.

- **Simulator**: `nx run-ios youtube-music-mobile`, then `nx start youtube-music-mobile` for Metro.
- **Your iPhone**: plug it in and run `nx run-ios-device youtube-music-mobile`. That builds the
  Release configuration, with the JavaScript bundled in, so it runs without Metro. Xcode needs a
  signing team: open `ios/Tunes.xcworkspace` and pick one for both the `Tunes` and `AddtoTunes`
  targets.
  - With a free Apple ID, apps expire after 7 days and need reinstalling. The share extension needs
    an App Group (`group.dev.wuguishifu.youtubemusic`), which may need a paid account. Without it,
    an iOS Shortcut in the share sheet that opens `youtubemusic://add?url=[Shortcut Input]` does the
    same job.
  - A paid developer account makes installs last a year.

Then in Settings, enter the service's address (reachable from the phone, e.g. over Tailscale) and
its `API_TOKEN`.

Tests: `nx test youtube-music-mobile` (queue order and volume levelling).
